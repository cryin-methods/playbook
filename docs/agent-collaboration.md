# Agent 协作惯例（详解）

> `methods/ai-collab/README.md` 的补充文档。这里是"为什么"的细节。

## 1. 为什么"复述确认"是唯一开工信号

AI 推进的隐含风险是"读心"——猜用户想要什么、然后做、然后错、然后返工。每次返工都消耗：

- 用户注意力（要 review 错误结果）
- AI tokens（要重做）
- 用户信任（"为什么它又猜错了"）

**对策**：在动手前复述一遍理解 + 列出子任务 + 等用户说"开始/可以/OK"才动。这 5 秒钟换 0 返工。

**反例**："用户说'你把 v3 移过来'，AI 没问'v3 在哪'就开始了 → 错。"

## 2. 为什么"追问 7 维"比"AI 自主判断"更划算

AI 自主判断 = 训练分布 + prompt 上下文 + 临时启发式。**有偏**且**易错**。

追问 7 维 = 把模糊目标拆成可验证的子问题。每个子问题问一次，错了也只错一个维度。

7 维（必扫）：

1. **目标** — 做出来干嘛用
2. **背景** — 为什么现在做、有没有相关东西
3. **受众** — 给谁看
4. **风格** — 语气、详略、正式度
5. **验收标准** — 什么算做好（要具体、能勾）
6. **雷区** — 什么样你会不满意
7. **决策偏好** — 做的时候遇到二选一，要我直接定还是列给你选

5 选扫：范围/边界、起点/现状、参考物、代价/可逆、后续动作。

## 3. 不可逆操作清单

| 操作 | 为什么不可逆 |
|---|---|
| 删数据 / 删数据库 / 删文件（不可恢复）| 一旦删了，没了 |
| 改硬件配置（BIOS / 注册表 / 防火墙规则）| 改错了系统崩 |
| 发到生产环境 / 发对外内容 | 一旦公开就收不回 |
| 涉及金钱 / 资金的转账 / 兑换 / 提现 | 钱没了就是没了 |
| 推到公开 GitHub 仓库 | 公开了就是公开的 |

**判定标准**：问自己"如果我做错了，能回滚吗？回滚成本多高？"——回滚不了 = 不可逆 = 必须用户拍板。

**反例**："AI 觉得'修一下 nginx 配置就好'→ 改 → reload → 站点全挂 → 改不回去"。

## 4. 角色互换：用户 vs AI

| 谁 | 给什么 |
|---|---|
| 用户 | 目标 + 不接受什么 + 必须达成的标准 |
| AI | 执行细节（跑命令 / 写代码 / 读文件 / 查路由） |

**用户管目标，AI 跑执行**——但执行层的不可逆操作必须让用户 approve。

**反例**："用户让 AI '修一下'→ AI 直接动 production 数据库 → 数据丢了"

## 5. 沉淀触发（什么时候写下来）

满足任一即触发：

| 触发条件 | 沉淀位置 |
|---|---|
| 同一类操作重复 ≥ 3 次 | `methods/<dim>/` 写规则 / 或抽 skill |
| 每次任务完成 | 写 JOURNAL（"这次跑对了什么 / 跑错了什么"）|
| 用户评价"我以为懂但跑错" | 立刻沉淀到 FACT.md / JOURNAL |
| 行为规则变更 | 改 SOUL.md |
| 6+ 月重要事实 / 决策 / 技术参数 | 改 FACT.md |
| 一次性事件 / 错误 / 坑 | append JOURNAL |
| 跨项目可复用工作流 | 抽到 `skills/`（独立仓库）|

**反例**："每次都说'SSH key 配错怎么办'→ 解决 5 次都丢了 → 第 6 次照样配错"

## 6. 凭据边界

| 行为 | 是否允许 |
|---|---|
| AI 读 .env 文件 | ✅ 允许 |
| AI 用 .env 内容注入 SSH / 脚本 | ✅ 允许 |
| AI 在 console / 对话 / file 输出 token 明文 | ❌ **仍然禁止** |
| AI 诊断 token → 只输出长度 + 前 8 + 后 4 | ✅ |
| 凭据明文存进 playbook / git | ❌ 绝对禁止 |

**理由**：泄漏 = 改起来麻烦。**流程麻烦优于 100% 安全**。

## 7. 信息冗余削减

高频信息应该一次性录到"项目索引"，避免每次新对话重问。

**索引文件**：`memory/secrets-index.md`（凭据） + 未来 `memory/projects-index.md`（项目）

**收录原则**：
- 同一类信息**第 2 次**出现在对话 → AI 主动问"要收录吗？"
- 凭据类不写明文（只写路径 + 变量名）
- 非凭据类（域名 / ssh 主机 / 项目根）可写明文

## 8. 复盘模板（任务结束跑）

```markdown
## [error] <type> | <desc>

**现象**：[实际跑出什么]
**期望**：[应该跑出什么]
**根因**：[为什么会这样]
**下次避免**：[怎么提前发现 / 提前避免]
**沉淀**：[JOURNAL append / FACT.md update / SOUL.md edit / 新 skill / 不沉淀]
```

跑 3 问：
1. 这次有没有 ENOENT / retry / 0 bytes / silent fail / 误解用户？
2. 这次有没有我以为懂但实际跑错的事？
3. 这次有没有可以未来避坑的发现？

任一是 → append JOURNAL（不必向用户展开细节）。

11 观点（按 2026-09 末状态）：

| # | 观点 | 关键约束 |

| D | 长期项目主动推进 | 主动查规矩 + 拆任务 + pre-mortem |
| E | 任务结束自查错误 | 3 问 silent fail |

| G | 自动沉淀触发 | 行为规则→SOUL；事实→FACT；事件→JOURNAL |
| H | 安全底线 | 读 .env ✅；输出 token ❌ |
| I | 沟通调参 | 精简度 7.5-8；杂度 3-3.5；隐藏模板化标签 |
